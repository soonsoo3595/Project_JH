# 백엔드 첫 목표

최종 갱신: 2026-10-21 (Asia/Seoul)
상태: 기본 빌드·Winsock 시작 템플릿 구현 및 검증, IOCP·송수신 구현 전

## 목표와 범위

독립 Windows IOCP 서버와 테스트 클라이언트로 연결·TCP/Protobuf 송수신·종료 처리를 먼저 검증한 뒤 UE를 연동한다. 로그인·MySQL·매칭·게임 로직은 이후 작업이다. 메모리 풀·Lock-Free 자료구조 등은 이 목표를 위해 선제 도입하지 않는다.

## 작업 순서

1. 개발 환경과 저장소 상태 확인: Visual Studio 툴셋·Windows SDK·CMake·vcpkg·Git 실제 상태를 확인한다. UTF-16 소스의 바이트 순서·BOM 및 도구 호환성을 확인한다.
2. 최소 빌드 기반: 서버와 테스트 클라이언트의 실행 타깃, 필요한 의존성과 빌드 절차를 구성한다.
3. 연결과 수명: IOCP 접속 처리, 세션 상태·소유권·종료 및 대기 중 I/O의 수명을 설계하고 구현한다.
4. 메시지 송수신: 프레이밍·최대 길이·Protobuf 스키마·검증 규칙을 정하고 요청·응답 왕복을 구현한다.
5. 첫 통합 확인: 두 클라이언트 접속과 송수신, 분할·병합 수신, 정상·비정상 종료와 서버 종료 시 자원 정리를 확인한다.

각 구현 단계는 사용자 명시 요청 범위에서 수행한다. PM은 코드 구현을 다른 세션에 자동 배정하지 않는다.

## 완료 판단 기준

- 같은 서버에 테스트 클라이언트 2개가 접속해 각각 요청·응답을 주고받는다.
- TCP 수신 경계와 메시지 경계가 달라도 올바르게 처리한다.
- 연결 종료·오류·서버 종료 시 세션과 비동기 I/O 자원이 안전하게 정리된다.
- 재현 가능한 실행 절차, 필요한 로그 및 실제 검증 결과·미검증 항목을 남긴다.

## 설계 시 결정할 사항

프레이밍 형식, 메시지 크기 제한·종류, 스레드 모델과 직렬화 경계, 세션·I/O 소유권, 종료 절차, 도구·의존성 버전은 아직 확정하지 않았다. 관련 담당 세션 등록도 필요하다.

## 현재 구현 결과

사용자 요청으로 CMake·vcpkg 빈 manifest·VS 2026 x64 Debug/Release 프리셋과 서버·테스트 클라이언트 진입점을 구성했다. 공통 라이브러리는 Winsock 초기화·해제만 담당한다. 두 구성의 빌드와 시작 검사 각각 2개를 통과했다. 위 완료 판단 기준 중 실제 통신·세션 정리는 아직 달성하지 않았다.
