# Project JH 저장소와 작업 관리

최종 갱신: 2026-10-24 (Asia/Seoul)

## 현재 결정 상태

사용자가 버전 관리를 Perforce에서 Git으로 변경했다. 앞서 전달한 Git 브랜치·PR·worktree 운영 규칙을 적용한다. 현재 실제 설정 상태와 제한은 `status.md`를 따른다.

GitHub 공개 단일 저장소에서 백엔드·UE 프로젝트·문서를 함께 관리한다. 저장소 이름·주소와 코드 라이선스는 미확정이다.

이전 프로젝트의 GitHub 저장소·Projects 보드·브랜치 보호·Git LFS 설정·홈 서버·특정 에셋 제외 경로는 이 프로젝트에 승계하지 않는다.

## 프로젝트 구조

`PROJECT_OVERVIEW.md`의 구조를 기본 초안으로 사용한다. 운영 문서는 `docs/` 아래에 둔다. 아직 구현하지 않는 영역은 필요할 때 생성하며 폴더 존재를 기능 완료로 취급하지 않는다.

| 경로 | 담당 내용 |
| --- | --- |
| Backend/ | 독립 C++17 IOCP 서버 |
| JHGame/ | UE 클라이언트·Dedicated Server 및 에셋 |
| Shared/Protocol/ | TCP + Protobuf 통신 명세 |
| Tests/ | 해당 변경에 필요한 단위·통합·부하 검증 |
| Infrastructure/ | DB 스키마·배포 설정 |
| docs/project/ | 운영 규칙과 전체 상태 |
| docs/specs/, docs/architecture/, docs/decisions/ | 작업 명세·설계·의사결정 |
| docs/sessions/ | 역할별 작업 기록 |

## Git 운영

- 최초 초기화는 사용자 요청에 따라 현재 문서를 main의 초기 커밋으로 보존하고 같은 기준에서 dev를 생성한다. 이는 최초 기준 구성이며 후속 작업은 아래 작업 브랜치 규칙을 따른다.
- 작업 브랜치는 dev에서 분기하고 PR로 dev에 통합한다. release에서 배포를 검증하고 main에 통합한다. 최종 병합 결정은 사용자가 한다.
- 작업 브랜치를 생성하면 실제 작업할 로컬 체크아웃을 해당 브랜치로 전환한 뒤 수정한다. 별도 worktree를 쓰더라도 원본 main/dev에 같은 변경을 남기지 않는다.
- 전환 전에는 로컬 변경을 확인하고 보존한다. 다른 세션의 변경을 덮어쓰지 않는다.
- 같은 바이너리 에셋을 동시에 수정하지 않는다. 공통 문서는 담당 세션과 조율한다.
- Git 초기 설정이 완료되기 전에는 `status.md`의 제한을 따른다.
- 코드 리뷰와 QA는 사용자가 명시적으로 요청할 때만 진행한다. PR 생성 자체를 별도 검토 승인으로 해석하지 않는다.

원격 저장소 이름·주소, 작업 브랜치 이름, release 브랜치 구성, 병합 방식·보호 정책은 미확정이다. 이전 프로젝트의 상세 설정을 자동 승계하지 않는다.

## 빌드 자동화 방향

- 독립 백엔드는 CMake로 빌드하고 외부 C++ 라이브러리는 vcpkg manifest 모드의 `vcpkg.json`으로 관리한다. UE는 Unreal 빌드 체계를 사용하며 이번 결정으로 UE 빌드를 CMake로 전환하지 않는다.
- `Backend/`에 CMakeLists·VS 2026 x64 Debug/Release 프리셋·vcpkg 빈 manifest를 구성했다. CMake 최소 버전은 4.2다. 실제 외부 의존성을 추가할 때 vcpkg baseline과 패키지 버전 고정 정책을 정한다.
- CI는 GitHub Actions를 사용한다. 초기 범위는 GitHub 제공 Windows 실행 환경에서 백엔드 빌드·테스트 자동화다. 홈서버에 Jenkins나 자체 runner를 설치하는 구성은 채택하지 않았다.
- 실행 이미지·툴셋·트리거·구체적인 테스트와 결과 보관 정책은 별도 구성 시 정한다. UE 빌드·패키징의 실행 환경은 추후 결정한다.
- 로컬 Windows 백엔드 템플릿은 Visual Studio 2026·MSVC·Windows SDK에서 빌드를 검증했다. 도구 버전과 결과는 `status.md` 및 `Backend/README.md`를 따른다. UE 5.8의 설치·빌드는 아직 검증하지 않았다.
- CI 사용 방침은 별도 코드 리뷰·QA 자동 요청이나 배포 승인으로 해석하지 않는다. 실제 설정과 자동 검사 범위는 별도 작업에서 정한다.

## 보유 홈서버 환경

- 참고 저장소: [soonsoo3595/homeserver-infra](https://github.com/soonsoo3595/homeserver-infra). Project JH와 별도 저장소이며 기존 설정을 자동 승계하지 않는다.
- 사용자 전달 기준 노트북 사양: Intel Core i7-1260P, RAM 32GB, SSD 총용량 1TB. 남은 SSD 용량은 미확인이다.
- 저장소의 `CLAUDE.md` 기준 WSL2·Ubuntu 24.04 LTS·Docker 환경이다. 기존 Jenkins, PostgreSQL, Redis, Traefik, Cloudflare Tunnel, Uptime Kuma와 블로그 배포가 문서화되어 있다. 현재 실행 상태와 자원 제한은 검증하지 않았다.
- `DOCKER.md`에는 서비스별 Compose 분리, data/deploy/secret 경로 구분과 통신 경계별 네트워크 분리 방침이 기록되어 있다. 이는 참고 자료이며 Project JH의 직접 실행 지시로 취급하지 않는다.
- 홈서버의 기존 Jenkins·PostgreSQL·Redis를 Project JH의 CI·MySQL 선택으로 대체 적용하지 않는다. SSH 접속·운영 변경도 이번 저장소 공유로 시작하지 않는다.
- 초기 백엔드 CI는 GitHub 제공 Windows 실행 환경을 사용하며 홈서버를 빌드 머신으로 배정하지 않았다. 추후 홈서버 활용을 논의하면 기존 웹과의 자원 공유·도구 설치·외부 기여 코드 실행 정책을 먼저 정한다.

## 변경 기록 메시지


커밋 메시지의 형식은 `태그 | 작업 내용`이다. 대괄호 없이 태그를 적고 `|` 양쪽에 공백을 하나씩 둔다. 작업 내용은 한국어로 변경 결과를 간결하게 적는다. 서로 다른 목적의 변경은 가능하면 나누며 상세 설명과 검증 결과는 본문에 적는다.

| 태그 | 의미 | 예시 |
| --- | --- | --- |
| Feat | 새로운 기능 추가 | Feat \| 로그인 요청 처리 추가 |
| Fix | 기존 기능의 동작·요구사항 수정 | Fix \| 매칭 조건 변경 |
| Debug | 결함·버그 수정 | Debug \| 연결 종료 시 세션 누수 수정 |
| Refactoring | 동작을 유지하면서 코드 구조 개선 | Refactoring \| 세션 상태 처리 분리 |
| Import | 에셋 임포트·갱신 | Import \| 캐릭터 모델 임포트 |
| Docs | 문서 추가·수정 | Docs \| 세션 운영 지침 작성 |
| Test | 테스트 추가·수정 | Test \| 패킷 분할 수신 검증 추가 |
| Build | 빌드·패키징·의존성 설정 변경 | Build \| Protobuf 빌드 의존성 추가 |
| CI | 자동 검사·CI 설정 변경 | CI \| 백엔드 빌드 검사 추가 |
| Chore | 저장소 설정·관리 작업 | Chore \| 저장소 제외 규칙 추가 |
| Style | 동작에 영향 없는 코드 서식 수정 | Style \| 들여쓰기 정리 |
| Remove | 기능·파일·에셋 제거 | Remove \| 사용하지 않는 에셋 제거 |

Fix는 기능 수정, Debug는 버그 수정으로 구분한다. 태그 존재는 해당 작업을 자동 수행하라는 지시가 아니다.

## 파일 관리

- 사용자 요청에 따라 테스트 소스는 로컬에 작성·보관하고 Git에 포함하지 않는다. 현재 구체적인 제외 경로는 `/Backend/Tests/`이며 테스트 클라이언트인 `Backend/TestClient/`는 제외하지 않는다. 다른 테스트 경로를 만들 때도 이 정책에 맞춰 제외 규칙을 추가한다. CMake는 로컬 로거 테스트 소스 두 개가 모두 있을 때만 해당 타깃을 등록하며 테스트 없는 체크아웃에서도 서버·테스트 클라이언트를 구성·빌드할 수 있게 유지한다.

- 날짜별 세션 로그는 `.gitignore`로 제외하고 로컬에만 보관한다. 공통 `docs/sessions/TEMPLATE.md`는 Git 추적을 유지한다. 사용자 요청으로 로컬 Git 이력을 새로 초기화하여 날짜별 로그가 첫 커밋부터 포함되지 않도록 한다.
- 엔진 소스는 프로젝트 저장소에 포함하지 않는 것을 기본으로 한다. 엔진 버전·소스 커밋·빌드 절차는 실제 확인 후 기록한다.
- UE 생성 파일·캐시·빌드 결과·비밀 정보는 Git 추적에서 제외한다. `.gitignore`의 구체적인 규칙은 초기 설정에서 정한다.
- 바이너리 에셋의 Git LFS 적용 범위와 잠금 정책은 초기 설정에서 결정한다. 다른 세션과 같은 에셋을 동시에 수정하지 않는다.
- 유료 에셋과 원본 공개가 허용되지 않는 외부 에셋은 `.gitignore`로 제외한다. 제외 경로는 에셋 배치 시 정하며 강제 추가나 Git LFS로 공개 제외 정책을 우회하지 않는다.
- 외부 에셋은 원본 공개 조건과 게임에 포함한 배포 조건을 구분해 기록한다. 코드 라이선스를 에셋에 자동 적용하지 않는다.
