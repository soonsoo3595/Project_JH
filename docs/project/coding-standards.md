# Project JH 코딩 규약

최종 갱신: 2026-10-15 (Asia/Seoul)
상태: 이전 프로젝트 규약에서 적용 가능한 항목을 옮긴 초기 문서. 확정 규칙과 제안을 구분한다.

## 적용 범위

- 독립 C++17 백엔드와 UE C++·Blueprint를 구분한다. UE 타입 접두사·UObject 규칙은 백엔드에 적용하지 않는다.
- `.Build.cs`·`.Target.cs`는 UnrealBuildTool용 C#으로 UE 관례를 따른다. 이전 프로젝트의 C# 백엔드·런처 규칙은 승계하지 않는다.
- 기존·외부 코드의 출처와 권리 표기를 보존한다. 작업과 무관한 일괄 서식·이름 변경은 하지 않는다.
- 아래 미확정 제안은 사용자 선택 전 확정 규칙으로 적용하지 않는다. 이 문서는 구현·formatter·CI·리팩터링 시작 승인이 아니다.

## 이전 문서에서 승계한 사용자 확정 규칙

- bool 부정은 `!Condition` 대신 `Condition == false`로 명시한다. 긍정 비교를 명시할 때는 `Condition == true`를 사용한다. 수치·enum 비교를 불필요하게 bool 비교로 감싸지 않는다.
- UObject 계열 포인터의 사용 가능 여부는 `IsValid(Object)`로 검사한다. 부정 분기는 `IsValid(Object) == false`로 작성한다. 일반 C++ 포인터에는 UObject용 `IsValid`를 적용하지 않는다.
- 에디터에서 개발자가 반드시 사전 할당하는 에셋은 개발 단계에서 필수 할당과 타입을 확인한다. 설정 누락을 처리하려고 런타임의 반복 검사·대체 동작을 추가하지 않는다. check/ensure의 구체적인 선택과 검사 위치는 별도 논의한다.
- 사전 할당 에셋과 런타임에 생성·교체·파괴되는 객체를 구분한다. 런타임 UObject의 유효성 검사는 필요한 사용 시점에 수행한다.

이전 프로젝트의 `LogWuwa` 로그 카테고리는 승계하지 않는다. Project JH의 로그 카테고리는 미확정이다.

## 이번 논의에서 확정한 규칙

- 코드 식별자는 영어로 작성하고 프로젝트 설명 주석과 진단 로그는 한국어로 작성한다. 외부 코드의 기존 주석은 보존한다.
- `auto`는 람다·장황한 반복자 등 타입을 직접 쓰기 어려운 경우로 제한한다. 단순히 초기화식에서 타입이 드러난다는 이유만으로 일반 변수에 확대하지 않는다.
- 게임 규칙·서버 판정·네트워크 로직은 C++로 구현한다. 에셋 연결·기본값·UI·표현에는 Blueprint를 허용한다.
- C++ 소스·헤더 파일은 UTF-16을 사용한다. 문서·설정·`.proto` 등 다른 파일은 도구별 요구사항에 맞춰 인코딩을 정한다. UTF-16의 바이트 순서와 BOM 정책, 생성 코드·외부 코드 처리 및 빌드 도구 호환성은 소스 작성 전 확인한다. 기존 파일을 일괄 변환하지 않는다.
- 소스 파일 인코딩은 네트워크 문자열·DB·로그 출력의 인코딩과 별개다. 이번 결정만으로 이들 데이터 인코딩을 UTF-16으로 확정하지 않는다.

## 백엔드 이름·서식 — 확정

- 일반 변수와 매개변수는 `sessionId`, `packetSize`처럼 camelCase로 작성한다.
- 멤버 변수는 camelCase 앞에 `_`를 붙여 `_sessionId`, `_packetSize`처럼 작성한다. `m` 접두사는 사용하지 않는다.
- 이번 결정은 독립 C++ 백엔드에 적용한다. UE 변수 명명 규칙으로 자동 확대하지 않는다.
- 클래스·구조체는 `Session`, `PacketHeader`처럼 PascalCase로 작성하며 UE 타입 접두사는 붙이지 않는다.
- 함수는 `SendPacket()`처럼 PascalCase로 작성한다.
- bool 변수는 별도 `b` 접두사 없이 `isConnected`처럼 작성하고 멤버는 `_isConnected`처럼 작성한다.
- 들여쓰기는 탭을 사용하고 표시 폭은 4로 설정한다.
- 중괄호는 새 줄에 작성하며 한 문장 조건문·반복문에서도 생략하지 않는다.

## UE 이름·서식 — 확정

- 타입은 UE 접두사를 사용한다. 예: `AJHCharacter`, `UJHGameInstance`, `FPlayerData`.
- 함수는 `RequestMatch()`처럼 PascalCase로 작성한다.
- 일반 변수·매개변수와 멤버 변수는 `SessionId`처럼 PascalCase로 작성한다. 멤버 변수에 별도 `_` 접두사를 붙이지 않는다.
- bool 변수는 `bConnected`처럼 `b` 접두사를 사용한다. bool 멤버에도 같은 규칙을 적용한다.
- 들여쓰기는 탭을 사용하고 표시 폭은 4로 설정한다.
- 중괄호는 새 줄에 작성하며 한 문장 조건문·반복문에서도 생략하지 않는다.
- 백엔드의 camelCase 및 `_` 멤버 접두사 규칙과 구분한다.

## UE 나머지 코드 규약 제안 — 미확정

이전 문서에서 채택 제안 또는 프로젝트 선택으로 제시한 항목이다. 전체 Epic 규약을 자동 의무화하지 않으며, 구현 시 사용하는 엔진의 기술적 제약은 별도로 확인한다.

- 표현: `nullptr`, `override`, 적절한 `const` 사용을 제안한다. 이름·서식은 위 확정 규칙을 따른다.
- include: 필요한 의존성을 직접 포함하고 `.cpp`의 대응 헤더를 먼저 둔다. 리플렉션 헤더의 `*.generated.h` 위치 등 UHT 제약을 준수한다. 불완전 타입으로 충분하면 전방 선언을 사용한다.
- 모듈: 실제 필요한 의존성만 선언하고 Public/Private 및 런타임/에디터 경계를 구분한다. 모듈을 미리 잘게 나누지 않는다.
- UObject 수명: 유지할 참조는 `UPROPERTY`와 `TObjectPtr`, 관찰 참조는 `TWeakObjectPtr`, 지연 로딩 에셋은 소프트 참조를 목적에 맞게 선택한다. UObject에 일반 C++의 소유권 도구나 `new/delete`를 적용하지 않는다.
- 비동기: 콜백·타이머·델리게이트가 객체 수명을 넘기면 약한 참조·취소·해제 또는 명시적 수명 보장을 설계한다. 유효성 검사만으로 임의 스레드의 UObject 접근이 허용된다고 가정하지 않는다.
- Blueprint: 확정된 C++·Blueprint 분담을 지키며 노출 범위를 필요한 만큼만 여는 것을 제안한다.
- 네트워크: 공유 게임 상태는 서버가 최종 판단하고 클라이언트 요청을 검증한다. RPC 호출 방향·소유 연결·신뢰성 이유를 설명한다. 지속 상태와 일회성 이벤트를 구분하고 Reliable이나 전역 도착 순서를 무조건 가정하지 않는다.
- 오류·로그: 정상적으로 발생할 수 있는 실패는 명시적으로 거부·반환·복구한다. 단정 매크로에 반드시 실행할 상태 변경을 넣지 않는다. 비밀번호·토큰·개인정보를 로그에 남기지 않는다.
- 주석: 비자명한 계약·단위·수명·실행 역할과 구현 이유를 기록하고 코드 내용을 반복하는 주석은 늘리지 않는다.

## 별도 결정할 사항

- 백엔드의 소유권·오류 처리·스레드 및 IOCP 작업 수명 규칙. 이름·서식은 위 확정 규칙을 따른다.
- UTF-16 바이트 순서·BOM 정책, 생성·외부 코드 처리, 도구별 파일 인코딩과 빌드 호환성.
- 로그 카테고리, 필수 에셋 검증 위치와 check/ensure 선택.

이전 프로젝트에서 확인한 엔진 문서·소스·실행 결과를 이번 프로젝트의 검증 사실로 승계하지 않는다. 구체적인 구현·검토 요청 시 실제 환경을 기준으로 확인한다.
