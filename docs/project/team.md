# Project JH 세션 운영

최종 갱신: 2026-10-24 (Asia/Seoul)

## 운영 합의

- 사용자는 단독 개발자이자 최종 의사결정자다. 현재 대화를 PM 채팅으로 사용한다.
- 직군별 Codex 세션이 메시지로 협업한다. 역할은 필요할 때 늘리며 공통 작업과 전체 상태 조정은 PM이 담당한다.
- 코드 구현·수정 및 코드 리뷰·QA는 각각 사용자의 명시적인 요청이 필요하다. 계획 제안·준비 확인·메시지 전달 권한은 구현이나 검토 시작 승인이 아니다.
- 지정된 프로젝트 세션 사이의 작업 요청·질문·검토 요청·결과 보고 메시지 전달은 허용된다. 외부 사람과 관련 없는 채팅은 제외한다.
- 작업 전달에는 목적, 사용자 요청 범위, 관련 명세, 담당 범위, 완료 조건과 의존성을 포함한다. 결정이 필요한 사항은 사용자에게 올린다.
- 공통 문서와 바이너리 에셋은 담당 세션과 조율하고 동시 수정을 피한다. 구현 세션은 로그를 갱신하고 전체 상태 변경은 PM에 요청한다.

## 역할과 등록 상태

| 역할 | 담당 | 등록 상태 |
| --- | --- | --- |
| PM | 공통 작업, 명세·의사결정·진행 상태 조정 | 현재 채팅 |
| 기획 | 게임 규칙·플레이 흐름·콘텐츠 명세 | 미등록 |
| 백엔드 | 독립 C++17 IOCP 서버, TCP + Protobuf 통신 | 백엔드 / `01a163b9-43b1-7c11-913a-f47d39ba8bac` / local |
| Git | 사용자 요청에 따른 저장소·브랜치·커밋·원격·PR 작업 | Git / `01a16d0d-e967-7fa3-b4cb-f7c57bd68c6c` / local |
| 언리얼 | UE 클라이언트·월드·던전 Dedicated Server | 미등록 |
| DB | MySQL 스키마·트랜잭션·영속 데이터 정합성 | 미등록 |
| 코드 리뷰 | 요청받은 코드·설계 검토 | 미등록 |
| QA | 요청받은 실행 검증·재현·결함 보고 | 미등록 |

역할 목록은 실제 채팅 생성 사실을 의미하지 않는다. 세션을 연결할 때 이름과 식별자를 기록한다. 파일 소유권과 병렬 작업 범위는 실제 작업에 맞춰 조율한다.

2026-10-22에 백엔드 채팅을 같은 로컬 프로젝트에 생성했다. 기존 `build/backend-template` 체크아웃과 미커밋 변경을 공유하므로 동시에 같은 파일을 수정하거나 브랜치를 전환하지 않는다. 초기 요청은 읽기 전용 인수인계이며 추가 구현을 배정하지 않았다.

## 코드 리뷰 기준

2026-10-24 사용자 요청으로 Git 채팅을 같은 로컬 프로젝트에 생성했다. PM·백엔드와 체크아웃을 공유하며 초기 요청은 읽기 전용 인수인계와 사용자 작업 요청 대기다. 세션 생성만으로 커밋·브랜치 전환·원격 연결·push·PR·병합을 실행하지 않는다. 공유 브랜치·파일 변경은 담당 세션과 조율한다.

- 변경 코드·관련 호출부·명세·검증 결과를 근거로 정확성, 설계, 유지보수성, 성능, 네트워크 동작을 엄격하게 검토한다.
- 사실과 가설을 구분한다. 결함은 파일·라인, 발생 조건, 영향과 개선 방향을 제시한다.
- 병합을 막는 결함, 권장 개선과 학습 질문을 구분한다. 개인 취향을 결함으로 보고하지 않는다.
- 설계 이유·대안·실패 조건 검증 질문은 현재 변경과 관련된 핵심에 집중한다.
- 별도 구현 요청 없이 코드를 수정하지 않는다. 검토 결과와 최종 병합 승인을 구분하며 최종 결정은 사용자가 한다.

## 기록과 인수인계

- 세션 로그는 `docs/sessions/YYYY-MM-DD/<역할>.md`에 역할별 하루 한 파일로 누적한다. 작업별·회차별로 나누지 않는다. 같은 역할의 여러 세션은 파일 담당을 조율한다. 날짜는 Asia/Seoul 기준이다.
- `docs/sessions/TEMPLATE.md`를 사용해 중요한 결정·변경, 실수·원인·재발 방지, 어려웠던 점과 시도·해결 과정, 필요한 인수인계만 간결하게 남긴다. 사소한 작업이나 도구 실행을 모두 기록하지 않고 중요한 내용이 없으면 파일을 만들지 않는다.
- 결론을 뒷받침하는 검증 결과가 있으면 실행·미실행을 구분한다. 실제 실행하지 않은 테스트를 통과로 기록하지 않는다. 검토 기록에는 필요할 때 대상 버전과 변경 범위를 남긴다.
- 날짜별 세션 로그는 로컬 전용으로 보관하고 Git에 추가하지 않는다. 공통 템플릿 `docs/sessions/TEMPLATE.md`만 Git으로 관리한다. 별도 체크아웃 간 필요한 기록은 메시지나 공통 상태·명세 문서로 인수인계하며 로그가 자동 공유된다고 가정하지 않는다.
